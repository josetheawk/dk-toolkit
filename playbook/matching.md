# Matching cookbook

One entry per lesson: **asm symptom → source idiom that fixes it**. Why. Which compilers it applies to.
Group entries under a heading per compiler family. Add an entry only after it produced an exact match.
How to identify the compiler and flags is in the platform notes.

## CodeWarrior (mwcc)

### What a per-function score misses

- **Every function is 100% but the unit's function order differs → `-inline deferred` emits functions in reverse source order.** Check a matching reference decomp of the same library before inventing a source order: Metrowerks' runtime and MSL were built with `-inline deferred,auto`, and their canonical sources reproduce the binary exactly that way. Keep one flag set per library. Detect: `./dk check` reports `layout: MISMATCH` with swapped offsets, which objdiff's per-function score alone misses.
- **objdiff's default scoring ignores what a relocation points at.** `m = 0.0f` and `m = 0.1f` both score 100% when the literal lives in a pool. Why: the default `functionRelocDiffs=none` is lenient. Apply: score with `-c functionRelocDiffs=data_value` (`dk check` does) and treat any data-section mismatch as a real bug, not noise.
- **objdiff scores a vtable by its bytes, which are zero where relocations go,** so an override declared in the wrong slot scores 100% and only the link catches it. Compare which function each slot points at (`dk check` does). Pure virtual slots are `0` (not a stub): a `0` slot means `= 0` in the base declaration.
- **objdiff counts our relocation against a section symbol (`...data.0+0xA0`) or an `@N` literal as different from dtk's label at the same address.** Treat them as equal when both are the same offset of the same section of the unit with the same bytes there (`dk check` does; each such function hand-linked byte-identical to the original).
- **Trailing zero padding in a data split is not a mismatch** (`dk check` allows under 32 bytes), but where a split may end is a dtk rule: see the platform notes on `gap_` symbols.
- **Weak copies explain data on both sides.** A base class with inline virtuals makes every TU emit a weak copy of its vtable, and the linker keeps the first. So a correct unit carries data its target lacks, and where the original linker discarded a duplicate it either left a zero block of the object's size or removed it (next rule). Apply: discount base-only bytes inside weak symbols the target doesn't define, and count a target zero block of a weak copy's size as explained (`dk check` does both; the link proves it). To reproduce such a block, make the unit *use* that class the way the original did, so the compiler emits the weak vtable at that position. Never pad with a zero array.
- **A discarded weak copy keeps its slot only in a section that an object the link keeps reaches through the section symbol (`...data.0+N`), at the end of the section too.** There its raw bytes stay and its relocations are dropped (a zero block for a plain vtable; a this-adjust word survives). A reference from a discarded object does not count. Otherwise the linker removes it and packs the kept objects at the alignment mwcc recorded in `.comment` (`dk check` models both, and reports a kept slot that moves the layout or the size). GC 1.3 points at local data through section symbols even from data (RTTI base lists, string pointers); 1.3.2 uses the objects' own names. Symptom: code exact, the target's RTTI base lists packed with no zero blocks, ours zero-filled around weak vtables. Apply: compile the unit with GC 1.3.2 (two units linked that way).
- **dtk folds literals a function reaches as base+offset into one auto label.** Split it at the real object boundaries (`dk symbol split ADDR`) so each source-level object pairs with its own target symbol.

### Data and static initializers

- **A TU-scope `const int` written in `__sinit` (`li` + `stw`) came from a non-constant initializer.** Reproduce it as `static const int x = f(0.25f);` with `inline int f(float s) { return s * 60.0f; }`, or from another call, rather than as a literal. A literal folds away and leaves no `__sinit` code.
- **Two pointer loops over adjacent array members that read a fresh `.sdata` word each iteration (`lwz r0, lbl_sdata; stw r0, 0(p)`), the second storing a register zero, came from by-reference fill helpers.** A `fill(first, last, const T& value)` template called with a literal binds the literal to a hidden writable static, so the value is reloaded every pass; a second call whose value is a typed null pointer keeps it in a register. Two inlined copies get two such statics. Apply: `Fill(m3C, m3C + 6, 0); Fill(m54, m54 + 6, (T*)0);` reproduced the ctor, the `.sdata` pair and the shared end pointer exactly.
- **`addi r3, r31, 0x64` string arguments off a shared data base score below 100% even though the bytes are identical, when the target's pooled string block is one dtk object (floats, then strings).** Why: objdiff compares the symbol each such immediate points into (data content from that address on), and separate `@N` literals differ from the target's one object. Apply: write the strings as one `static char names[N] = "a\0\0\0b\0..."` with the exact padding and put it in source order after the floats, then pass `names + offset`. If another unit externs the object's first member (`lbl_...[4]`), define that member as a global with the link name.
- **The target keeps a TU's unreferenced data (RTTI of a weak vtable, class-name strings of discarded inline copies) → `#pragma force_active on` after the includes, left on to the end of the file.** Why: the pragma sets the force-active flag (in `.comment`) on every object of the TU, compiler-generated ones included; the linker still drops weak duplicates but keeps everything else, unreferenced functions too. `force_active reset` before the end keeps the strings but not the RTTI emitted at end of TU, which matches TUs that keep only the strings. Detect: code and data exact, the link is short in `.sdata`/`.data`, and the target holds objects your compile has that nothing references (often just past the unit's split end). A unit that is only a `__sinit` is a different case: see the platform notes. When the link comes out longer instead, a weak copy of ours that the target lacks survives because the first copy, in an earlier not-yet-matched object, still has an auto name (`fn_ADDR`): to the linker ours is the only definition and force_active keeps it. Give that copy its mangled name (`dk rename`) and ours becomes a dropped duplicate.
- **Literal arguments passed by `const&` in a constructor's initializer list (`m2(0.0f), m3(0.0f)`) become one `.sdata` word each, emitted in the order the list is *written*, not the members' declaration order; the ctor's `li r4, lbl@sda21` rows name which word each init uses.** When the unit's functions are all exact but the full link's first differences are `li r4` offsets in the ctor (`.sdata` 100 % per object because the words are equal), reorder the initializer list so the member whose init takes the highest-addressed word comes last; the code order stays the declaration order. Verified: `m19C(0.0f), m1AC(0.0f), m18C(0.0f)` linked where the declaration order did not.
- **Several statics of one class whose `__sinit` stores all N destructor-registration records first and then N objects (`obj = base + k * size`, the second built as `addi r3, base, off` then `addi r3, r3, size`) were one array initializer.** Write `static T arr[N] = { T(...), T(...), ... };`; separate `static T a = T(...); static T b = T(...);` interleave record, object, record, object in `.bss` and shift every later offset. Detect: the `__sinit` is the only function below 100%, with `.bss` offsets differing by multiples of the record size (12) and the element size. Verified: a six-element array took a `__sinit` from 92.6% to exact. That split address form is GC 1.3.2's; GC 1.3 folds it into one `addi r3, base, off + k * size`. A unit that is otherwise exact on 1.3 but has this `__sinit` is a 1.3.2 unit with one inlining decision left to fix (see the auto-inline row below).

### Classes

- **RTTI and vtable blocks in another order than the target's, with the class's destructor among the last functions before `__sinit` → the destructor was inline (defined in the class).** Its out-of-line copy and the vtables are emitted at the end of the TU, and that gives the target's order. A non-inline destructor emits the vtable earlier. Detect: code exact, `.data` matching up to the first RTTI name.
- **Each class's out-of-line destructor follows its constructor.** The base's inline destructor gets its out-of-line copy right before the first derived destructor, and inline virtuals referenced only by vtables go to the end of the unit. Symptom: all functions 100% but `layout: MISMATCH`, with destructors bunched at the end. Fix: define the destructors out of line in source order (`X::~X() {}`), rather than inline in the class.
- **Virtual-base thunks** are named `@<this-adj>@<vbase-off>@<method>`. When a class has a virtual base, name its own unknown virtuals `vf<slot>_<Class>` so they don't clash with the base's `vf<slot>`.
- **Virtual-base thunks in slot order mean those slots are one name overloaded (on `const`).** MWCC emits a class's virtual-base thunks in reverse slot order, but an overload set's in slot order, and its inline copies likewise. Detect: all functions exact, `layout: MISMATCH` with two adjacent thunks swapped. Apply: give both virtuals one name, the second `const` (getters call that one), and rename the second's symbols to the `...CFv` name. Verified in toys and on two real pairs: two units' layouts became exact.

### Codegen idioms (mwcc, C++), each verified by an exact match

`dk close` tries these rows mechanically: a beam search over source rewrites, each keyed to its symptom and applied at the lines the mismatches come from (a rewrite that fits several sites of one shape is also tried at all of them at once), with each candidate kept only when it is byte-exact, nothing else in the unit gets worse, and it adds no device.

| asm symptom | source idiom |
|---|---|
| Stores in reverse order (z, y, x) | Chained assignment `a = b = c = K`, which stores the last one first |
| `fcmpu f, 0` vs `fcmpu 0, f` | `if (f)` vs `f != 0.0f` |
| `x * 0.5f` with `x` loaded before the constant | `x / 2.0f` (a literal `x * 0.5f` loads the constant first) |
| An add of 0.0 that survives | A variable: `float d = 0.0f; x += d;` (a literal 0.0f is folded away) |
| The target's frame is smaller, with several block-scoped objects sharing one stack slot | Those objects were temporaries (`out = T(x);`), which reuse one slot; named block locals (`T s(x); out = s;`) get a slot each |
| A conditional branch whose target is one block off, with all else equal | A statement sits on the other side of a block boundary: inside the `if` in the target (or only part of the block, e.g. the `qsort` alone, is conditional) |
| A constructor called on an address with no null test, where ours wraps `new (p) T(x)` in `addic.`/`beq` | MWCC null-checks every placement new. The target called the constructor directly: `p->T::T(x)` (MWCC accepts it) |
| Stack slots | Aggregate locals sit above scalars, bigger aggregates higher. Within one size, named locals come first (the earlier declaration higher), then temporaries, then the locals of inlined functions in reverse declaration order. A local below the temporaries (a call's return slot, a by-value argument copy) was declared in an inline helper |
| A loop differing only in register allocation (`li rX,0; mr rY,rX`; older compilers `addi rY,rX,0`): the loop's local starts as a copy of a zero the caller already holds | The loop was an inlined helper; write it as an inline function taking the values it reads. When its instructions are an already-matched sibling's body, give that body an inline helper and keep the sibling plain (it stops matching if it calls the inline). Find these from the target alone: `dk inlines --scan` lists every open function's zero copies and matched-function bodies, biggest unmatched bytes first. Measured on functions closed this way: 2/3 flagged; on random matched functions 7/30 flagged, nearly all of which do inline something, so it is a lead, not a verdict |
| An inline's weak copy (or a function) in an unexpected place | It lands right after its first user (a call through the vtable counts); at its definition when it is declared in the class and defined later in the unit; after `__sinit` when only the static initializer constructs its class (the TU's thunks and factory functions go there too) |
| An inline's weak copy one or more functions later than its first user | The copy is queued and written out at the next top-level *data* declaration (`extern T x;` or a definition); function declarations do not flush it. A function returning a class by value is also held back to such a point. Move a data declaration the original plausibly had between the first user and the next function. Verified: a unit linked once a destructor sat right after its first user. |
| `name$N` plus an `init$N` guard in `.sbss` | A function-local static; size the guard so `.sbss` pairs |
| `strcmp(...) == 0` gives `srwi` vs `extrwi 8,19` | Returned as `bool` vs `int`/`unsigned char` |
| `clrlwi.` (byte re-mask) before a branch where the target has `cmpwi` on a call's result | The callee is declared to return `bool` (a const member predicate); declare it `int` in the header and the definition |
| `cmplwi` vs `cmpwi` against 0 or a small constant | The field or local is unsigned vs signed. Check locals too: an `unsigned char` walk variable gives `cmplwi`, an `int` gives `cmpwi` |
| `cmplwi r, 0` followed by `ble`/`bgt` where ours has `beq`/`bne` (an unsigned `> 0` the compiler did not fold to `!= 0`) | The operand is a pointer: `p > (void*)0` (an integer `x > 0u` is canonicalised to `x != 0`); type the field as a pointer and keep the odd compare |
| `li r0, ~K; and` where ours has `rlwinm` (`x &= ~K` on a field) | The field is unsigned (`unsigned int`/`unsigned long`); a signed field gives `rlwinm` |
| A function repeats its own body 2-3 levels deep, the inner levels calling helpers (even itself) that the outer level inlined | A plain recursive function: `-inline auto` inlines the recursion and its helpers until the inline budget runs out, so write the natural recursion with the helpers as inlines and let the budget cut it |
| `lfs`/`stfs` per field vs `lwz`/`stw` words | Assigning an all-float struct vs initializing a by-value local |
| A float struct local kept in memory across calls (`stfs` to its slot right after the loads, dead stores kept, later loads forwarded) where ours keeps its members in callee-saved FPRs | The class has a user-declared destructor, even an empty inline `~T() {}`: the destructor takes `this`, so the object stays in memory. A trivially destructible struct, array or copy-constructed local is promoted to registers. Verified: two quaternion blends exact (80% and 97% before) |
| A pooled float one ulp off | Write the exact literal (e.g. `0.025000002f`) |
| `fmuls` operand order: constant first vs variable first | `q * 2.0f` puts the literal first; `x *= K` puts the variable first |
| `fadds` operands swapped (ours `x + p`, target `p + x`) where `p` is a product in the same expression | Name the product in a local (`float y = v * k; out = y + x;`); written inline, CW may put the plain operand first |
| A global re-read after every compare or store | The global is `volatile` |
| `if (!a \|\| !b) return;` shape: `bne next; b exit` | Exactly that `\|\|` early return (not two separate `if`s) |
| `bge; b; fmr` vs `cror` for a min/max | A ternary `t < 0 ? t : 0` gives the branches; a plain `if` gives `cror` |
| A min whose result gets its own saved register (`mr r6, rB; bge; mr r6, rA`) where ours reuses a dead temporary's register | A ternary `a < b ? a : b` (its result is a new value); `r = b; if (a < b) r = a;` lets `r` share a register |
| A field tested through `neg; or; srwi.` (its `!= 0` made into a value) before a `beq` | An inline member returning `m ? true : false`, tested in the `if`; a copy of the field the branch needs is read inside the branch |
| An inline getter's result is copied to a saved register after the null test (`cmplwi r3, 0; mr r29, r3`) where the target loads it straight into the saved register in both branches | Drop the cast on the getter's result (`const char* t = Text();`, cast at each use): a cast makes the local a separate value |
| A comparison passed to an `int` parameter has a `clrlwi r, r, 24` in ours only | `a <= b ? 1 : 0`: the bare comparison is a `bool` widened at the call |
| Two halfwords packed the other way round: `rlwimi rD, hi, 16, 0, 15` against the target's `slwi; mr; rlwimi rD, lo, 0, 16, 31`, or the reverse | Swap the `\|` operands. The right operand is the base the left one is inserted into: `(lo & 0xFFFF) \| (hi << 16)` shifts `hi` and inserts `lo` |
| `mulli; addi; lfsx` on an array element | The element was read through a reference: `T& e = a[i];` |
| `lfsx` + `addi` (indexed, base+index) where the target loads `lfs off(r3)` | The member was read through the sibling accessor the class already has for that array (`Obj(i)->m`), not by indexing the raw array member in the caller. Try the neighbouring accessor before inventing a form |
| Indexed stores (`stbx`, a recomputed base) where the target does `add; stb` off a base kept in a register | A hoisted base local: `S* base = m1C; e = base; ... base[i].m4 = 1;`, with the store going through `base`, not through the field |
| Saved registers differ across consecutive loops | Declare one shared `int i` for all the loops |
| Callee-saved register numbers swapped between locals (or with `this`) | The rank rule (gamecube-mwcc.md, Register allocation): named locals rank by declaration order, temporaries and inline results above them. A value made by `c ? a : b`, an inline with two returns or an inline member (`NumActors()`, `Settings()->Profile()`) takes r31 ahead of locals declared before it; `if (c) x = a; else x = b;`, a free helper or a plain load keeps declaration order. `dk regs` shows each variable's register |
| A field the function already loaded is loaded again inside later branches | Those uses go through the class's inline accessor (`r.fn_Right()` for `m8 + mC`), not the field |
| A first argument loaded before a later argument's nested call | It was an inline call itself (`f(Settings(), 13, g(t))`); a plain load is evaluated after the nested call |
| A small mask kept in a register (`li r0, 3` ... `and r5, r5, r0`) where ours has `clrlwi` | On a register variable, the compound form: `n &= 3` (CW folds `n = n & 3` into a rotate). For a mask on a load or a field (`li`/`lis; subi` then `and`), a 64-bit-typed constant (`& 0xFFFFLL`) does it; the compound form does not |
| A global that a call passes is loaded before stores that may alias it (ours loads it after them) | The stores and the call are an inline helper's body, and the global is its argument: inline arguments are evaluated at the call, before the body |
| A pointer parameter the loop advances (`dst += n`) is copied to its saved register late (after the first loads) and ranks like a local declared there | The loop advances a local copy: `float* dst = out;` at the top. Advancing the parameter itself schedules and ranks its copy differently |
| A loop over a global array copies the address into another register (`addi rA, …; mr rB, rA`) and steps rB | The loop indexed the array (`g[i].f = …`): the strength-reduced pointer is the address temporary itself. A named pointer local (`T* p = g; … p++`) is a separate variable and gets the copy |
| Array-of-objects static init adds the element size to a base address (`addi r3, r30, 0x24; addi r3, r3, 0x24`) | GC 1.3.2 or later (1.3 folds the offset); if 1.3.2 then inlines a constructor the target calls, use `-inline noauto` with `static inline` helpers |
| Literals in a different pool order | Pool order is creation order: reorder the expressions that first use them (`dk diff --literals` lists the target's order and first users) |
| A function's literals start the pool ahead of an earlier function's, or one block's literals lead its function's | That block was an ordinary helper defined before the user and auto-inlined (its own copy dead-stripped): its literals are created at its definition. Float literals are created in source order, int-to-float conversion constants after the function's other literals |
| An implicit `operator=` emitted at the end of the unit | Give the struct an inline user `operator=` (or copy fields), so no implicit one is generated |
| A 4-byte empty `__sinit` | A global of a class with an empty inline constructor |
| A global loaded into r3 and copied (`lwz r3, g; cmplwi r3, 0; mr r31, r3`) where the target loads it straight into r31 | Assign in the condition, `if ((p = g) != 0)`, or read it through the class's inline accessor; `T* p = g; if (p != 0)` makes the copy |
| An inline's result tested in r3 and only then copied to a saved register (`cmplwi r3, 0; mr r30, r3`) where ours keeps it in the saved register | A cast on the inline call, even a redundant one: `T* p = (T*)cast<T>(w);`; in a lookup loop, the element read straight through the container (`(T*)list.Get(i)`) instead of a one-line wrapper inline (`Item(i)`); for a call result with a fallback, a copy tested on the original: `T* f = Find(); T* t = f; if (f == 0) t = root;` |
| `cmpwi r3, 0; li r3, K; beq end; li r3, 0` where ours is branchless (`cntlzw`/`neg`/`andc`) | Name the call's result and set the return value before the test: `int ok = f(); int r = K; if (ok) r = 0; return r;` (`return f() ? 0 : K` and early returns both fold) |
| A min/max over several values that loads each operand just before its compare (`lwz c; cmpw t, c`), where ours loads them all first | Successive statements (`m = a < b ? a : b; m = m < c ? m : c;`): nested inline `min(min(a, b), c)` calls evaluate all their arguments before the inlined bodies. A bounding box of four points matched that way |
| A clamp that loads the upper bound first and keeps the result in the lower bound's register | Write the clamp with its own compares (`if (lo > hi) lo = hi; if (v < lo) return lo; if (v > hi) return hi; return v;`), not nested `min()`/`clamp()` inlines |
| Several `#pragma dont_inline` pairs in one unit, each stopping one auto-inline | Try the unit flag `-inline noauto` with the pragmas removed: if no function scores lower, the TU was built that way (seven units' pragmas became the flag that way, and one dtor went from 95% to 99%) |
| A call the target keeps (`bl f`) where ours auto-inlines `f`, defined earlier in the unit | Try GC 1.3 for the unit first: it auto-inlines less than 1.3.2 (three units matched that way). Check for a TU boundary between them too: a class change, weak inline copies or factories after a `__sinit` mean the unit is two TUs, and splitting it makes the call a `bl` with no source change. Otherwise the original `f` was bigger before inlining: write its own inline helper calls out by hand (one expanded `Clear()` was enough). The limit counts statements: measure the gap in a scratch copy with `((void)0);` lines (never land them), then find a natural form that is that many statements longer. Three matches: a constructor's `m = g += 4;` written as `int id = g + 4; g = id; m = id;` (+2), `return 0;` written as `int result = 0; … return result;` (+1), and a switch whose cases each `return` written as cases that assign one result variable and `break`, with a single `return` (+1 per case: a 12-statement gap closed, the switch compiled the same). An extra store or call changes the code, and an inline helper call counts as the statements of its body. An early return also counts (`if (!x) return;` in place of wrapping the body in `if (x) { … }`, +1): `f`'s own code is the same either way, so record that choice as open in the faithfulness audit |
| In a search loop over `m4[i]`, the target increments the counter before the strength-reduced offset (`addi rI, rI, 1` then `addi rO, rO, 4`) where ours does the reverse | Declare the index `int` (signed), still compared with the unsigned count (the compare stays `cmplw`). This applies to inline find helpers (`for (int i = 0; i < list.count; i++) { T* t = list.Get(i); if (t && t->name == name) return t; }`) |
| Two call arguments evaluated right to left (the third argument's inlined call first, held in a saved register) where ours goes left to right | Make the inline accessor one expression (`return m10 ? 0 : (m8 ? f(m8) : m4);`). An accessor written as statements (`if (…) return …;`) is expanded in argument order |
| `cntlzw; extrwi rD, r0, 8, 19` (a bool widened) where the target has `cntlzw; srwi rD, r0, 5` | The comparison's value is used as an int straight away: `c ? 2 : 1` or `(c ? 1 : 0) + 1`, not `(a == b) + 1`; for a returned test, `int t = a < b; return t == 0;`. A test used twice (`cntlzw`/`extrwi` once, then both arms of two ternaries): a `bool z = x == 0;` local, then `z ? a : b` |
| A field re-read in the target after a call through `addi r0, rOff, K; lwzx` (offset unfolded) where ours loads it once through a pointer | An inline accessor with an `unsigned int` index read twice (`Count(r, i) > 0`, then `f(Count(r, i))`) |
| An inlined member ctor's self-pointer stores folded into the outer object (`stw r5, 0x20(r3)`) where the target stores through the member's own address (`addi r5, r3, 0x20; stw r5, 0(r5); stw r5, 4(r5)`) | The ctor writes through a local copy of `this`: `Link* self = this; self->m0 = self; self->m4 = self;` (an intrusive list head made empty) |
| A function that sets no return value uses volatile registers one above the target's (`lwz r5, 0xac(r1); mr r3, r5` before a call where the target loads r3 straight) | It returns `void`. Declared `int` and falling off its end, it keeps r3 reserved to the end (one 0x540-byte switch went from 95.8% to exact) |
| An `asm {}` block's first instruction scheduled above the store before it (ours `li r3, 4` ahead of `stb r0, 0x14(r31)`; the target stores through r3, then runs the asm) | GC 1.3: its scheduler leaves inline asm where it is, 1.3.2 moves code into it. When a neighbour function needs 1.3.2, look for a TU boundary between them (4-7 pad bytes in .data): one unit became a 1.3.2 TU and a 1.3 TU, both linked |
| A call's struct-valued result passed straight to a callee, in a frame smaller than ours by the struct's size | The parameter is `const T&` bound to the temporary: `g(f(x))`, not a named local plus a pointer. `T r(f(x));` matches a target that copies the result; `const T& r = f(x);` matches one that reads fields from the return slot |
| `cmpwi; beq case; b default` where ours gives `bne` | A `switch` with one `case`, not an `if` |
| `beq L; b end` early return, or `if (x == 0) {..} else {}` (an empty else) | `switch (x) { case 0: break; default: return; }`, or `switch (x) { case 0: ..; break; }`. A dead `b` after a then-block is `if (c) {..} else { return; }` |
| A comparison tree (`beq; blt; b`) on a small selector, ours a plain `if` chain | A `switch` whose empty cases and shared labels shape the tree (`case 0:` plus empty `case 1:`, `case 2:`; or `case 1: case 2: default:`). Invented case sets that reach 99% but never exact are a guess: stop there. Apply a whole-function rewrite with `--replace` when per-line variants fail to compile |
| The loop's exit taken by a branch to the loop test, where the target branches past it | An `else { i++; }` tail became `break; } i++;` (the increment after the `if`, the exit as a `break`) |
